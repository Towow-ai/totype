# ADR-0001：S0 稳定性优先

- 状态：Accepted
- 日期：2026-08-21
- 回滚基线：`/Applications/Verbatim Voice.app` 0.3.47 (50)

## 决定

Verbatim Voice 在 S0 验收关闭前只接受稳定性工作。热词扩展、修改学习、模型评测 GUI、本地模型升级、iOS、新 Provider 和视觉重设计全部冻结。

用户关键路径固定为：

```text
停止录音 → 封闭音频流 → 选择首个合格结果 → Unicode dispatch → 收起浮窗 → idle
```

AX 验证、Provider 清理、模型对照、音频归档、历史写入、修改观察和存储维护不得阻塞这条路径。每个会话拥有独立 Provider 生命周期；任何超时、取消或迟到事件不得污染下一会话。一次 `sessionID` 最多 dispatch 一次。

## 不可破坏护栏

- Soniox 主模型，阿里云非阻塞热备，双云失败才运行本地整句兜底；
- 原话模式固定开启，不使用 LLM 改写、总结或结构化；
- 自动插入只发送 Unicode 事件，不访问通用剪贴板；
- 已 dispatch 即为用户路径终态，后台证据不得重试、弹预览或重新打开浮窗；
- 固定 Bundle ID、固定签名身份、单一正式 App 路径、idle 才允许原子更新；
- 构建、安装或单次成功均不等于稳定验收。

## 音频启动隔离补充（2026-08-24）

真实故障证明 `AVAudioEngine.start()` 在其他应用使用麦克风、CoreAudio 重建聚合设备时可能同步阻塞数十分钟。该系统调用不得再运行在 MainActor、会话状态机或恢复协调器上。

- 每次启动使用独立候选引擎和专用串行队列；成功且未过期后才成为 active engine；
- 前台恢复路径的单次等待上限为 2 秒；超时候选进入 quarantine，迟到音频与迟到成功都不得发布；
- 阻塞调用无法安全强杀，因此最多允许两个尚未返回的候选，避免无限堆积线程；
- 每次恢复拥有递增 generation；被新设备事件取代的旧任务不能接受候选、拆除新引擎或改写状态；
- quarantined 系统调用终于返回时立即唤醒新一轮恢复，不必等完整退避周期；
- 旧 active engine 的 stop/reset 同样离开主线程；
- 仍以当前 generation 的首个新 PCM 为 ready 证据，`start()` 返回不等于恢复。

## S0 出口门槛

- 正常 `stop_to_dispatch`：P50 ≤ 1 秒，P95 ≤ 1.5 秒；
- Soniox 异常且阿里云已有 final：3 秒内插入；
- 双云异常：12 秒内本地完成或明确失败；
- 500 轮确定性故障注入无死锁、重复提交或跨会话污染；
- 100 次真实跨软件会话零卡死、零重复插入、零剪贴板污染、零意外权限提示；
- 未达到全部门槛时不得发布或宣称 `0.4.0 Stable`。

## 变更纪律

每次只推进一个稳定性切片，并保留上一版 `.app.disabled`。任何门槛失败立即停止发布、保留现场并恢复最近已验收版本，不用相邻功能掩盖失败。
