# Totype · 设计系统 v2

日期：2026-10-01。设计源文件（`screens/*.html`、`tokens.json`、`Tokens.swift`、`shared/` 生成器等）不在本仓库内；公开仓库只含 `docs/design/` 下的截图，见文末。原设计交付物包括：`overview.png`（总览）、`redlines.png`（标注）、`screens/*.html|png`（每个画面）、`icons/`、`tokens.json`、`Tokens.swift`、`shared/`（token CSS、mockup kit、渲染脚本、token 生成器）。所有数值由 `shared/gen-tokens.py` 一处生成，三份输出一致。

## 0. 设计陈述

这套设计成立的理由只有一个：所有形状都来自键盘，而麦克风只有三种形状。iOS 27 系统键盘的几何（键高 43、行距 11、键距 6、圆角 7、无阴影，都是在模拟器上量出来的）是键的形状语言；在它的三行键区中央，待命是一个圆（Ø112），正在听是这个圆横向展开成的胶囊（6 列宽），提交是实心圆。主 App 底部、灵动岛、Mac 浮窗用同一组形状的不同尺度。颜色只有十二级灰和 iOS 的录音红，红只在麦克风正在采集时出现在波形上。

最得意的地方是键盘从待命到录音的变化：圆横向拉成胶囊，两侧长出 ✕ 和 ✓ 两个圆，圆心线、列栅格、命中区都不动。

还不确定的两处：一是首页去掉了大录音按钮，改为底部一枚键，这依赖键盘已经成为主入口；二是引号图标的尾巴曲线只在 1024 和 16 像素两头看过，中间尺寸要在 Icon Composer 里再校一次。

## 1. 原则（7 条，每条可检验）

| # | 原则 | 检验方法 |
|---|---|---|
| 1 | 原话是主角：转写文字用最大的正文（17/26），其他文字不超过 15pt，且比它浅 | 任一画面里字号最大、颜色最深的文字块必须是原话（标题页除外） |
| 2 | 一个形状语言：键是圆角 7 的矩形（其他圆角只从 {10, 14, 20, 44} 里取，连续曲率）；麦克风只有三种形状——圆 = 待命，胶囊 = 正在听，实心 = 提交 | 稿子里找不到这些值以外的圆角；任何画面里的麦克风/录音控件都是圆或胶囊 |
| 3 | 一个颜色，一个语义：录音色 = 麦克风正在采集，别处不出现；没有品牌色（2026-10-01 起浅色为中灰 #8A8D93、深色为降饱和的红 #E8766D，见 §13.2） | 任何非录音态画面里像素级搜索不到录音色（现为 #8A8D93 / #E8766D 的波形与点） |
| 4 | 几何来自测量，不来自手感：键盘尺寸与系统键盘实测一致，App 的列栅格与键盘共用 | `redlines.png` 的列线同时落在键盘键边和首页麦克风键边 |
| 5 | 状态不靠颜色区分：待机 / 首次 / 正在听 / 识别中 / 已插入 / 失败 各有不同形状与一句话 | 把稿子转成灰度后仍能逐一分辨 |
| 6 | 线是 1 物理像素，面是实色：无大面积玻璃、模糊、渐变；材质只在 Mac 浮窗和灵动岛 | 分隔线在 @3x 截图里恰好 1 像素；背景色值只有 token 里的 |
| 7 | 动效可中断、可关闭：所有过渡是弹簧或 ≤200ms 的缓动，Reduce Motion 下全部改为 150ms 淡入淡出 | 动效表里每一行都有「可中断」与「减少动态」两列 |

## 3. 参考研究（一手优先；标明学到的手法与出处）

### 3.1 iOS 27 系统键盘（一手：模拟器实测）

方法：`xcrun simctl` 启动 iPhone 17e（390×844，@3x，iOS 27.0 24A434），用 `defaults write com.apple.keyboard.preferences DidShowContinuousPathIntroduction` 跳过滑行输入教程，打开信息的新建会话让键盘弹出，`simctl io screenshot` 取浅/深两张，用 PIL 逐像素扫描。截图留在会话临时目录，未入库。

|---|---|---|
| 字母键 | 32.33 × 43 pt | 同 |
| 水平键距 / 边距 | 6 / 6.33 pt | 同 |
| 行距 | 11 pt（行节距 54） | 同 |
| 键圆角 | 约 7 pt，连续曲率（顶边起弧点距角 20 px） | 同 |
| 键阴影 | 无 | 无 |
| 键底色 | #FFFFFF（字母键与功能键相同） | #464646 |
| 键盘底色 | #E2E3E8 | #222223 |
| 键字色 | #050505 | #FBFBFB |
| 第二行缩进 | 半个节距（19.2 pt） | 同 |
| Shift / 删除键宽 | 43.3 pt，与字母间距 14 | 同 |
| 底行 | 123 = 41.3，表情 = 41.7，空格 = 185，换行 = 89.7 | 同 |

学到的手法：键没有阴影，形状全靠底色对比；功能键不再用深一档的灰；行距比键距大（11 vs 6），所以竖向比横向松。本稿所有键盘数值直接取这些值；393pt 宽时键宽按公式 `(W − 12 − 54) / 10 = 32.7` 推算。

### 3.2 HIG · Typography（一手：developer.apple.com，2026-10-01 抓取）

- SF Pro tracking 表（1/1000 em）：11: +6，12: 0，13: −6，15: −16，16: −20，17: −26，20: −23，22: −12，23: −4，24: +3，28: +14，34: +12，44: +8。本稿 `tokens.json` 的每个字号都带这列值；SwiftUI 里用 `.tracking(pt)`，pt = size × 值 / 1000。
- 动态字体默认档（Large）：Large Title 34/41，Title 1 28/34，Title 2 22/28，Title 3 20/25，Headline 17/22 Semibold，Body 17/22，Callout 16/21，Subhead 15/20，Footnote 13/18，Caption 1 12/16，Caption 2 11/13。本稿字阶照此，唯一例外是转写正文 17/26（中文需要更松的行距）。
- 「In a running app, the system font dynamically adjusts tracking at every point size」：所以只有 mockup 需要手动 tracking，代码用系统字体即可。

### 3.3 HIG · App Icons（一手）

- iOS/macOS 图标 1024×1024，交方形图层，系统做圆角掩膜；分层图标 = 背景层 + 前景层，用 Icon Composer 标注 default / dark / mono 变体。
- 「Prefer clearly defined edges in foreground layers」「Let the system handle blurring and other visual effects」：前景引号是硬边矢量，不加高光、阴影。
- 「Include text only when it's essential」：图标里没有字。
- 外观变体：default、dark、clear light/dark、tinted light/dark，系统会为缺的变体自动生成；本稿给 default / dark / tinted 三版，tinted 交灰阶前景。

### 3.4 HIG · Live Activities（一手）

- 三种岛态 + 锁屏：紧凑态「leading 与 trailing 要读成一条信息，紧贴相机，不加 padding」；最小态「显示更新的信息而不只是 logo」（计时器的做法）；展开态要与紧凑态位置关系一致。
- 「Use consistent margins and concentric placement … subtracting the margin」：展开岛 44pt 圆角，边距 14，按钮圆角 30。
- 锁屏标准边距 14pt；不能自定义紧凑/最小/展开的背景色。
- 计时用系统 timer 文本（代码里已是 `Text(timerInterval:)`），不自己每秒推送。

### 3.5 Linear · How we redesigned the Linear UI（一手）

- 主题由 LCH 生成：「perceptually uniform … a red and a yellow with lightness 50 appear equally light」；整个主题只定义三个变量（base、accent、contrast），其余 98 个变量由算法派生。
- 本稿照做：灰阶在 OKLCH 里定义 L 梯度（浅：1.0 → .18，深：.14 → .97），色相 262、彩度 0.003（与系统灰 #8E8E93 同向的极淡冷调），由脚本转成 sRGB。改一个 L 值即可全局重算。

### 3.6 Rauno Freiberg · Invisible Details of Interaction Design（一手）

- 可中断（interruptibility）是现实世界的属性，动画必须像翻书一样随时能被打断；本稿所有弹簧都用 SwiftUI 的可重定向弹簧，不用 `withAnimation` 里的固定时长。
- Fitts 定律：目标越大越近越快。✓ 键做成 71×151 的整列，是键盘上最大的目标，且在拇指停留处。

### 3.7 未取得一手资料、按常识处理的部分

- Things 3 的列表行高与留白：没有量到。本稿列表取 iOS 表格的 44pt 最小行高、16pt 内缩、1 物理像素分隔线，原话行上下 12pt。
- 语音备忘录的波形参数：没有量到。波形参数是本稿的提案（见 §7.3），需真机对照。
- Vercel Geist 的颜色页是客户端渲染，抓取只拿到标题，未参考其数值。

## 6. 布局与对齐

- 4pt 基础栅格，8pt 节奏；文字左缘 16；可点区域 ≥ 44×44（胶囊按钮 28 高但命中区扩到 44）。
- 键盘列栅格（W 为屏宽）：键宽 `k = (W − 12 − 54) / 10`，节距 `k + 6`，第 i 列 x = 6 + i·节距。

| 屏宽 | 键宽 | 节距 | 麦克风键（4 列） | 空格键 |
|---|---|---|---|---|
| 375 | 30.9 | 36.9 | x 116.7 · 宽 141.6 | 124.6 |
| 393 | 32.7 | 38.7 | x 122.1 · 宽 148.8 | 142.6 |
| 430 | 36.4 | 42.4 | x 133.2 · 宽 163.6 | 179.6 |

  功能键固定宽：Shift / 删除 44，ABC / 123 41.3，地球 41.7，换行 89.7。竖向：状态行 44 → 4 行（43，行距 11）→ 底内缩 8 → 安全区 34，总高 291。横屏：行高 36、行距 7、状态行 34（代码里的 compact 分支）。
- 光学对齐：麦克风图形上移 2pt（底座让重心偏下）；对勾与叉按几何中心；状态行里的小对勾用 14pt、2.6 线宽，与 15pt Medium 文字等重；引号图标的圆心线在 41.5% 高度。
- 圆角：键 7，高键 10，卡片 14，浮层 20，灵动岛 44；嵌套时内 = 外 − 间距，不小于 0。SwiftUI 用 `RoundedRectangle(cornerRadius:style: .continuous)`。
- 分隔线：`1 / displayScale`（@3x 0.333pt，@2x 0.5pt）；mockup 用 `--hair: 0.3334px`，已在 @3x 截图里验证恰好 1 个物理像素、不糊。

## 7. 组件规格

### 7.1 键盘状态行（44pt）

| 状态 | 左文字 | 右侧 |
|---|---|---|
| 会话待命 | 空（有「已用阿里云」时只显示这句）；不显示倒计时（§13.1） | — |
| 会话未开启 | 点麦克风开始 · 首次会打开原话，再滑回来 | — |
| 正在听 | **正在听** · 说完点一下波形 | — |
| 识别中 | **识别中**… | — |
| 已插入 | **已插入 49 字** | 胶囊「↶ 撤销」，5 秒 |
| 失败 | **没插入** · 网络不通，录音已留在历史 | 胶囊「重试」 |
| 待插入 | 一行预览（省略号） | 实心胶囊「插入」 |

### 7.2 键盘键区

待命 / 首次 / 已插入 / 失败 / 待插入：一个 Ø112 的圆，圆心在三行键区中心，命中区第 4–7 列整高。
正在听：✕ 圆 Ø72（圆心在 1–2 列中线）、胶囊 226.2 × 112（3–8 列：48 根波形柱 + 计时，作为一组垂直居中）；9–10 列不放东西。命中区 ✕ 2 列、完成 8 列（3–10 列）× 151，点胶囊即完成（§13.1）。
识别中：同两形，✕ 置 35% 不透明，波形收成一条线，线上一段深色在流动，计时转次要色。
字母层：系统几何原样；底行 [123][地球][空格][麦克风][换行]。

### 7.3 波形

主 App 15Hz 写入 32 段电平，键盘读取后插值到 60Hz；每根柱高 = max(2, h × level^0.55 × 1.4)（与 Mac 现有曲线一致）；attack 30ms、release 180ms 的指数平滑；静音时柱高 2，形成一条点线，让「没声音」可见；低电量或 Reduce Motion 下退化为 3 档柱高、15Hz 直接绘制。

### 7.4 主 App

首页：大标题 → 会话行（52，麦克风轮廓 + 文字 + 「结束」胶囊）→ 1 物理像素线 → 分组列表（今天 / 昨天，右侧字数与段数）→ 底部 98pt 区（麦克风键 56 高 + 8 + 34），上缘 1 物理像素线。
详情：原话 17/26 → 元信息 → 回放行（44 方键 + 60 根灰柱，已播部分转主色 + 时间）→ 三个胶囊 → 两个折叠行（引擎与时间线、重新转写的版本）。
返回页：左上「↖ 点左上角的 ◀ 返回」+ 一行说明（状态栏原来显示时间的地方写着来源 App，比如「◀ 微信」；也可沿底部横条右滑）、中央录音点 + 大计时、底部与键盘相同的 ✕ + 胶囊（§13.1）。

### 7.5 灵动岛 / 锁屏

只在一次听写的「启动中 / 正在听 / 识别中」存在，听写结束即结束活动，会话待命不出现（§13.1）。紧凑：左录音点（录音）或麦克风轮廓（启动、识别），右计时 15 Semibold tabular；最小：只剩点或轮廓；展开：371 宽、44 圆角、14 边距，标题行 + 波形 + 两枚 38 高文字按钮「取消」「完成」（圆角 30 = 44 − 14，「完成」实心）；锁屏：14 边距，24pt 图标 + 名称 + 状态、34pt 计时 + 波形、同样两枚按钮。识别中没有按钮。

### 7.6 Mac

浮窗：30pt 胶囊，`regularMaterial` + 0.5pt 发丝描边 + 一层 18pt 模糊、6pt 偏移、28% 的投影；四态见 `screens/mac-overlay.png`。菜单栏面板 300 宽，13/18 字；历史窗口 780×560，侧栏 300。

## 8. 动效与触感

| 转换 | 属性 | 参数 | 可中断 | Reduce Motion |

## 13. 修订 2026-10-01 · 麦克风键改为圆（评审意见）

评审通过了整体方向，只要求待命态的麦克风键不要方的、要圆的。我把它贯彻成一条形状规则，而不是换一个圆角：

**圆 = 待命，胶囊 = 正在听，实心 = 提交。** 键是矩形（它们是系统键盘的东西），麦克风不是键，它是会变形的那一个对象，所以它用自己的形状族。

| 位置 | 待命 | 正在听 | 提交 |
|---|---|---|---|
| 键盘（三行键区） | 圆 Ø112，圆心在键区几何中心（x 196.5，键盘坐标 y 119.5） | 胶囊 226.2 × 112（第 3–8 列，端半径 56）；两侧 ✕ / ✓ 圆 Ø72，圆心在第 1–2 列与第 9–10 列中线（x 41.7 / 351.3） | ✓ 圆实心（fill/key-prominent） |
| App 底栏（56 高） | 圆 Ø56，同一条 x 中线 | 胶囊 226.2 × 56 + 两侧圆 Ø56 | ✓ 圆实心 |
| 返回页 | — | 与 App 底栏相同 | 同 |
| 灵动岛 | 紧凑态本身是胶囊（系统形状）；展开态按钮为 30 圆角胶囊 | 同 | 完成按钮白底实心 |
| Mac 浮窗 | — | 30pt 胶囊（不变） | — |

尺寸的理由：Ø112 = 14 × 8，在 151 高的键区上下各留 19.5；比它大会碰到行距，比它小会显得像普通键。胶囊高度沿用 112，所以变形只改宽度，圆心不动。两侧圆 Ø72 = 9 × 8，略大于两列的 71.4，视觉上和 Ø112 构成 1 : 1.56 的主次。命中区没有缩小：仍是整列矩形（待命 4 列、✕ 2 列、胶囊 6 列、✓ 2 列，都 151 高），所以按圆的边缘外面一点也会命中，与系统键的容差一致。

变形参数（见 §8 两行）：胶囊宽 112 → 226.2 用 `.spring(duration: 0.36, bounce: 0.12)`；两侧圆 scale 0 → 1 用 `.spring(duration: 0.32, bounce: 0.2)` 延迟 40ms；收回用 `.spring(duration: 0.32, bounce: 0)`。全部由同一个状态值驱动，弹簧随时可被反向重定向；Reduce Motion 下改为 150ms 淡变，不改形状。

### 13.1 修订 2026-10-01 晚 · 录音态去掉 ✓，待命不显示倒计时（真机试用反馈）

**录音态只剩两个形状：居中的胶囊和左侧的 ✕ 圆。** 原来右侧的 ✓ 实心圆与点胶囊是同一个动作，试用下来觉得多余。界面上同一个动作只给一个目标，形状语言因此更干净：圆 = 待命，胶囊 = 正在听，点胶囊 = 完成，✕ = 取消。「实心 = 提交」在键盘上不再需要单独的实心圆，提交的反馈改由胶囊自己给：按下时 fill/key → fill/key-pressed、scale 0.96，松手后波形收线进入识别中。

| 位置 | 正在听（新） | 命中区 |
|---|---|---|
| 键盘 | ✕ 圆 Ø72（1–2 列中线，x 41.7）+ 胶囊 226.2 × 112（3–8 列，圆心 x 196.5 不动）；9–10 列空 | ✕ 2 列；完成 8 列（3–10 列），都 151 高 |
| App 底栏 / 返回页 | ✕ 圆 Ø56 + 胶囊 226.2 × 56，同一条 x 中线；右侧空 | 同上，56 高 |
| 灵动岛展开 / 锁屏 | 文字按钮「取消」「完成」，「完成」实心；去掉按钮里的 ✕ ✓ 图形 | 系统按钮 |

几何没有为了“平衡”去挪胶囊：胶囊仍居中，圆心与待命圆重合，所以圆 ⇄ 胶囊的变形参数（§8、§13）不变，只是少了右侧圆的 scale 动画。右侧两列不画东西，但命中区归「完成」：用户已经习惯伸手点右下角，那里点下去仍然是完成；完成不是破坏性操作（有 5 秒撤销），所以宁可把这块空地给它，也不留一条点了没反应的死区。✕ 只占左两列，取消依然需要明确地点在左边。

灵动岛和锁屏保留「取消」「完成」两个文字按钮，按同一原则判断：那里的胶囊（波形）不是可点目标，点活动本身是打开 App，所以「完成」只能靠一个按钮，取消也一样；两者都是这里唯一能做的事，留着。改动只是去掉图形，写成字，并按“实心 = 提交”让「完成」实心。

**会话待命不再显示倒计时，也不在灵动岛和锁屏出现。** Live Activity 只存在于一次听写的启动中、正在听、识别中，听写结束即结束。键盘状态行在待命时是空的，只在有事可说时出现（待插入、失败、已插入、已用阿里云、需要打开 App 等）。会话剩余时间只在主 App 首页的会话行里显示。理由：待命是后台状态，用户不需要被它的倒计时提醒；一直挂在灵动岛上的倒计时读起来像“还在录”。代价：键盘在后台发起的听写，iOS 可能拒绝在后台新建 Live Activity，这时那一次听写在灵动岛上没有显示（键盘本身照常显示录音态），诊断日志会记下 `liveActivity.start.failed`。

**返回页**：iOS 26.4 起没有自动返回原 App 的公开 API，机制不变，只把指引说清楚：箭头指向状态栏左上角（灵动岛左侧、原来显示时间的地方），说明那里会写着来源 App 名，以「◀ 微信」为例，并给出第二条路（沿底部横条右滑）。App 拿不到来源 App 的名字，所以不画一个假的「◀ 微信」，免得盖住真的链接。

### 13.3 修订 2026-10-01 · Mac 浮窗"还是浓"：材质等级、投影与数字字体（0.3.78）

评审连续两次反馈浮窗"浓"；第一次调淡了录音色，第二次把罩色从 86% 降到 52%、描边与投影减半，反馈是"颜色淡了，透明度没有淡，框还是浓"。这次先找原因再改数。

**真正的原因有三层，前两次都没碰到第一层。**

1. 材质等级。浮窗用的是 `.thinMaterial`。macOS 上这一档本身约 80% 不透明，并且会提升背景饱和度（vibrancy），所以它自己就是一块乳白/乳黑的面；再往上叠一层白色罩色，52% 和 86% 的差别被压在最后十几个百分点里——这就是"透明度没有淡"的来源。罩色是加法，材质已经近乎不透明，罩色再怎么减都减不出透明。
2. 投影。`0 6px 18px` 的投影在 30pt 的小胶囊外面画了一圈 12%/32% 的灰晕；在浅色桌面上，这圈晕比胶囊本身还显眼，看起来像"框"。深色模式下再加 9% 的白描边，就是一条清楚的亮边。
3. 体量与字重。30pt 高、12/10 内边距、13pt Medium（中文回退为 PingFang SC Medium）——Medium 的中文在小胶囊里偏黑，让整块更"满"。

**改法（`VVMac.*`）**

| 项 | 之前（0.3.77） | 现在（0.3.78） |
|---|---|---|
| 材质 | `.thinMaterial`（≈80% 不透明 + 饱和度提升） | `.ultraThinMaterial`（系统最轻一档，≈50% 底色） |
| 罩色 pillTint | 白 0.52 / #202022 0.55 | 白 0.30 / 黑 0.26（只为守住文字对比度） |
| 投影 | 6pt 偏移、18pt 模糊，黑 0.12 / 0.32，另加 1pt 0.03 | 只保留接触阴影：1pt 偏移、2.5pt 模糊，黑 0.10 / 0.28；无环境阴影 |
| 描边 pillStroke | 黑 0.07 / 白 0.09 | 黑 0.06 / 白 0.07 |
| 分隔线 / 键帽底 | 0.14 / 0.16，0.07 / 0.12 | 0.12 / 0.14，0.06 / 0.10 |
| 胶囊 | 30pt 高，左右 12 / 10 | 28pt 高，左右 11 / 10 |
| 文字 | 13pt Medium | 13pt Regular |
| 胶囊内次要文字 | fg/secondary（#5A5B5C / #9D9EA0） | 新 token `pillSecondary`：#414244 / #DDDEE0，比 fg/secondary 深一档，因为底是半透明的 |

对比度按"材质 50% 底 + 罩色"的模型取最差背景计算：

| 情形 | 胶囊等效底色 | 主文字 | 胶囊内次要文字 |
|---|---|---|---|
| 浅色胶囊压在纯黑区域上 | #A6A6A6 | 7.70 | 4.13 |
| 浅色胶囊压在中绿壁纸上 | #C6D6BB | 12.27 | 6.58 |
| 深色胶囊压在纯白窗口上 | #696969 | 5.03 | 4.05 |
| 深色胶囊压在中绿壁纸上 | #2D3D21 | 10.69 | 7.6 |

主文字在任何背景上 ≥ 4.5；次要文字（"识别中"、引擎提示）在两个极端背景上 4.1 左右，真机材质还会再提一点亮度，若仍嫌弱，下一步是把罩色提到 0.36，而不是回到 thinMaterial。

**数字。** 原来所有数字都是 13pt Medium 加 `monospacedDigit()`。用字样对照（`DesignPreview` 新增 `type` 目标，`impl-shots/mac-type-specimen.png`）看到两处"微妙"：一是 SF Medium 的数字比旁边的 PingFang Medium 更黑、更挤；二是 tabular 把"49""0.55"这种静态数字撑成"4 9"，与中文之间的节奏断掉。改为：数字与中文同为 13pt Regular；`monospacedDigit()` 只用于会跳动的值（浮窗计时、撤销倒计时、菜单面板计时），"已插入 49 字"这类静态计数用比例数字。字号、基线不动——试过 13.5pt 和基线 −0.5，差别小于渲染误差，不值得引入半点字号。SF Mono 与 SF Rounded 都试过，一个把中文行拉散，一个与 SF Pro 字形冲突，不用。

### 13.4 修订 2026-10-02 · 语音层删除键移到右上角

评审意见是“删除键应该在右上方，而不是右下方，这样顺手”。语音层的删除键从底行移到键区首行的第 9–10 列，底行改为 [ABC][地球][空格][换行]，地球键仍只在系统要求时出现。本节取代 §7.2 与 §13.1 里“9–10 列不放东西、完成占 3–10 列整高”的写法。字母层不变。

**几何（393 宽）。** 删除键面 = `span(8, 2)` × 首行：x 315.6、y 0（键区坐标），71.4 × 43，圆角 7，图形 `delete.left`，按下换 `delete.left.fill`。它的右缘 387 与下面换行键的右缘对齐，两键落在同一条右边线上。宽度取两列而不取字母层的 44：键区上半部只有它一个键，两列宽正好落在栅格上，也给拇指更大的目标。待命圆 Ø112 的右缘在 252.5，离删除键 63；录音胶囊右端在 309.6，比删除键左缘低 32.5（胶囊上缘 y 19.5、删除键下缘 y 43），两者最近处约 14pt，不相碰。空格吃掉原来删除键的位置：有地球键时 190.3，没有时 238.0。横屏沿用同一公式（行高 36、行距 7）。

**命中区。** 删除键的命中格是键面加半个键距，右边和上边贴到键盘边缘：x 312.6–393、y 0–48.5（横屏 0–39.5）。录音时的「完成」让出这一格：胶囊所在的第 3–8 列仍是整高，第 9–10 列只从 y 48.5 开始到键区底部。两块完成区与删除格在 x 312.6、y 48.5 处无缝拼接，没有重叠，也没有点了没反应的死区。✕ 仍是第 1–2 列整高，不受影响。App 底栏和返回页没有删除键，完成区保持原来的 8 列整高。

**录音时删除键照常可用。** 删字只改输入框里已有的文字，不碰正在进行的录音：音频、计时、波形都不受影响，识别结果完成后照常插入在光标处，撤销也照常按“光标前文本与插入后一致”判断。说话时发现前面多了一个字，顺手删掉，比先停下录音更符合“不打断录音”的原则。代价是 §13.1 里“右侧空地归完成”的范围缩小了：第 9–10 列首行原本点下去是完成，现在是删除。习惯伸手点的是右下角，那一块（第 9–10 列下两行）仍是完成；而删除键在待命和录音两种状态里都在同一个位置，肌肉记忆不会被状态切换打乱。长按连删（450 ms 后开始重复、逐步加速、约 20 次后按词删）行为不变；删除键在所有麦克风状态下是同一个视图，状态切换不会中断正在进行的长按。

**旧底行的一个偏差。** 原来底行的公式多算了一个键距，换行键右缘落在 393（贴屏边）而不是 387（右边距）。语音层这次按新公式改正；字母层的底行仍是旧公式，等字母层下一次改动时一并修。

受影响并已重出的截图：`kb-idle`、`kb-idle-dark`、`kb-first`、`kb-starting`、`kb-listening`、`kb-listening-dark`、`kb-finalizing`、`kb-inserted`、`kb-failed`、`kb-pending`。改动的文件：`KeyboardUI/KeyboardKeys.swift`（`KeyboardBottomRow` 语音层去掉删除键）、`KeyboardUI/VoiceKeyboardView.swift`（`voiceLayer` 放置删除键）、`Design/MicControl.swift`（新增 `finishTopRightReserve`，默认 0，只有键盘传入删除格的下缘）。
