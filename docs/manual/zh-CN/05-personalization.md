# 05 个性化

[English](../en/05-personalization.md)

“个人资料”页让识别结果更贴近你的用词：写下你的行业背景、登记常用术语、为常被听错的词设置别名。这些内容主要影响识别引擎收到的提示，不会在识别之后改写你说的话；唯一直接改动文字的是别名的恢复，而且需要另一个引擎佐证。本地引擎不使用个人资料里的任何词。改你的话改多少，主要在这一页决定；收尾的插入偏好见 [06 改多少](06-literal-rules.md)。

打开方式：历史窗口左上角点人像图标。

![个人资料页](../../images/profile.png)

## 说话人背景

用一两句话写你是谁、常谈什么，例如“说话人是一名产品经理，常谈用户研究、季度规划和数据看板。”它作为背景发给 Soniox，帮助引擎在听不清时偏向你常说的领域。只写身份、常谈话题和常用词，不要写指令。阿里云和本地引擎不使用这一项。

## 术语表

每行一个词，例如产品名、人名、缩写。每次录音时术语表都会发给云端引擎，Soniox 把它作为识别上下文，阿里云把它作为热词。“阿里云热词权重”（1 到 5，默认 4）控制热词对阿里云结果的影响，词越容易被听错，越可以调高；调得太高也会让不相关的音被误识别成这个词。

“加入开发者入门词包”会额外加入一份通用技术词表，如 GitHub、MCP、Docker、TypeScript 等，默认关闭。你的个人词库里的词排在前面。

自动学习：“设置”页“高级与诊断”里的“观察插入后的人工修改”默认开启。你在目标输入框里改动刚插入的文字，同一个修正出现两次以上时，Totype 会把修正后的词自动加入个人词库，Totype 会提示“已自动学习热词”。它之后会随录音发给云端引擎。不想要这个行为就关掉该开关，已学到的词可以在个人词库里删除。

## 误听别名与恢复

有些词引擎总是听成同一个错误写法，比如把“Sonnet”听成“Sonet”。在“误听别名”一节，左边填正确的词，右边填常被听成的写法，多个写法用逗号分隔，点“添加”。别名以小标签显示，点标签上的“×”删除。

别名的恢复很克制。 Totype 只在满足全部条件时才替换：

1. 本次识别结果里出现了这个别名。
2. 你同时配置了 Soniox 和阿里云两个 Key，另一个引擎已经返回了同一段音频的结果。
3. 另一个引擎在同一位置听到的正是你登记的正确写法。

任何一个条件不满足，文字保持引擎的原样。别名可能本身就是一个真词（比如“不是 SKU，是 skill”），所以必须有第二个引擎佐证。本地引擎和本地后备的结果不参与佐证，所以只用本地模式时别名不会生效。别名本身不会发给云端。原始的引擎输出始终保存在历史记录中。

## 转写提示词

默认提示词要求逐字听写、保留重复、口头语、否定、自我修正和中英文切换，不要总结、改写或补全，并按真实停顿使用自然的简体中文标点。你可以改成自己的偏好，比如标点怎么用、口头语留不留。

它的作用：提示词随每次录音发给云端引擎。Soniox 把它当作识别上下文（也放进通用说明），阿里云把它作为一条上下文消息，最多使用前 400 个字符。本地引擎不使用它。

它的局限：它是写给语音识别引擎的提示，不是写给大模型的指令。识别之后没有任何模型改写文字，所以效果取决于引擎，也不保证每次都照做；标点和口头语比改写措辞更容易受影响。偏离“逐字”会让引擎倾向于整理你的话，建议一次只改一点，在历史里对比结果。

## 导出与导入

“导出配置…”把以下内容保存为一个 JSON 文件（默认文件名 `verbatim-profile.json`）：术语表、个人词库与别名、说话人背景、转写提示词、识别与插入偏好、录音保留设置。文件不包含 API Key、历史和录音，可以放心在自己的几台电脑之间迁移。

导入的过程是：

1. 点“导入配置…”，选一个 JSON 文件。
2. 页面显示“导入‘文件名’将改变：”和逐项变化，例如“术语表：新增 3 个，移除 1 个”。
3. 点“应用导入”确认，或点“取消”。确认前不会写入任何内容。
4. 确认时，当前配置先备份到该文件所在的文件夹，页面里的状态行显示备份文件名。

文件里缺少的字段保持原值不变，手写的或旧版本的文件也能导入；文件版本比应用新时会提示先更新应用。词库部分只做合并：已有的词保留，只补充缺少的别名，不会删除任何词。
